# BUILD-031 — Economy, ranks, missions, shop, marketplace, and clans

**Local status: Active — implementation through Clan competition rewards (migration 0047); authenticated privacy/browser review remains.**

## Implemented in the first slice

- Migration `0024_economy_ledger_ranks` adds an append-only EXP/Coin ledger with unique idempotency keys and versioned rank policies/tiers.
- `GET /v1/me/wallet` derives EXP and Coin balances from ledger rows and reports the caller's applicable rank track.
- `GET /v1/me/ledger` is cursor-paginated and always scoped to the authenticated account; cursors from another account are rejected.
- Admins can create immutable rank-policy drafts and activate them. Activation validates a zero starting threshold and strictly increasing tiers, retires the previous policy, and audits the change.
- Student/staff rank is derived from lifetime EXP and the currently active policy; no seasonal reset or client-provided balance/rank is accepted.
- Migration `0031_rank_role_tasks` adds role-specific staff promotion requirements and deduplicated trusted metric receipts. Staff rank requires both the configured EXP threshold and every task configured for the account's staff role. Metrics use registered trusted domain events; manual tasks require an evidence request and an independent Admin decision. Admin policy editing, staff progress/evidence request, and Admin review queue are connected to `/ranks`.
- Connected `/wallet` and `/ranks` interfaces show live balances, transaction history, rank progress, and an Admin policy editor.
- Migration `0025_missions_rewards` adds versioned registered-key missions, per-user cycle progress, trusted-event receipts, and idempotent reward records.
- Admins create daily/weekly/one-time mission versions using only registered event keys. Changes to an existing daily/weekly mission take effect at the next local cycle boundary; current progress stays pinned to its version.
- Practice attempts/correct answers, attendance check-ins, lesson completion, and submitted assessments update mission progress inside the same transaction as the trusted source event. Daily/weekly rewards are automatically ledgered; one-time rewards require an authenticated idempotent claim.
- Connected `/missions` screen shows trusted progress and one-time claim controls; Admins can publish mission versions. Rewards update the same EXP/Coin wallet ledger.
- Migration `0026_achievements` adds versioned event-backed achievements, earned tiers, reward receipts, and equipped titles. Trusted events update achievement progress and reward the wallet transactionally; only earned configured titles can be equipped. Connected `/achievements` UI supports student progress/title management and Admin version creation.
- Migration `0027_shop_inventory` adds a supported item catalog, idempotent purchases, inventory, and stock tracking. `GET /v1/shop/items`, `POST /v1/shop/purchases`, `GET /v1/me/inventory`, Admin item creation, and supported inventory activations are connected to the `/shop` and `/inventory` pages. Purchases lock the actor, recheck role, stock, purchase cap, and Coin balance, then debit the ledger, decrement stock, record the purchase, and grant bound inventory in one transaction.
- Shop effects are explicitly allowlisted. Cosmetic, title-token, and practice-boost activations consume the owned item; create-clan and rename-clan cards are consumed by the atomic clan domain routes. No grading effect is supported.
- Added a focused API lifecycle test for Admin catalog publishing, Coin debit, replay-safe purchase, and exactly one inventory grant.
- Migration `0028_marketplace_listings` adds explicit tradeable policy and fixed-price listing escrow. Listing creation reserves only an owned, available, unbound item from a tradeable catalog entry. Purchase locks the listing and inventory, rechecks expiry, role eligibility and buyer balance, transfers the item and appends buyer debit/seller credit ledger rows atomically. Cancel and expiry return the item; settlement and listing creation use account-bound idempotency keys. Public listing views omit seller identifiers and expose only a viewer-relative `isMine` flag.
- Migration `0029_marketplace_offers` adds Coin/item escrow offers. Offer creation atomically debits Coin to escrow and/or reserves an eligible tradeable item; seller accept transfers both sides and credits Coin, while reject/cancel/expiry releases reservations and refunds escrow. Offer decisions and per-account offer creation are idempotent. Expired offers and listings are released as marketplace state is read or acted on.
- Migration `0030_marketplace_disputes` adds party-scoped listing/offer disputes. Disputed inventory and offers are frozen from concurrent settlement. Admin resolution is blocked for an Admin who is a party to the dispute; an independent Admin can uphold escrow or reverse it with new compensating ledger entries. Original ledger rows remain unchanged, all decisions are audited, and the Admin queue is exposed through `/v1/admin/marketplace/disputes`.
- Connected `/marketplace` UI supports listing, direct purchase, cancel, Coin offers, and incoming/outgoing offer decisions. `/shop` Admin form controls whether a catalog item can be traded.
- Connected marketplace UI also provides trade history, dispute reporting, and an Admin dispute-resolution queue with uphold/reverse actions.
- Focused lifecycle tests cover fixed-price settlement, replay, item-for-item settlement, rejected Coin refunds, accepted offers, expired escrow release, dispute freezes, independent Admin review, and compensating reversals.
- Migration `0032_staff_events` adds course staff events and participant awards. Authorized course staff fund a reserve from their own Coin balance; result approval is allowed only after the event ends, accepts active course students, derives awards from the stored budget/mode, pays once by idempotent ledger keys, and audits the decision. Cancellation refunds the organizer and cannot reverse a paid event.
- Migration `0033_clans` adds clans, active/invited/requested membership, internal roles with an allowlisted permission set, and an append-only Clan EXP ledger. Create/rename require an owned, bound, available matching shop card and consume it atomically. A partial unique index enforces one active clan per user. Join requests, invitations, decisions, role assignments, leave, public rankings, and member-only details are connected to `/clans`.
- Migration `0034_clan_level_policies` adds immutable Admin-created/activated level policies and thresholds. Activation recalculates every clan and refuses a member cap below current membership. Admin awards are audited and idempotent; Clan EXP updates level, cap, icon and color from the active policy. The connected Clan workspace covers level policy editing, membership, roles, rename, approved EXP awards, and leaderboard.
- Migration `0035_clan_visual_effect` persists the active level color projection. Migration `0036_clan_wars` adds Admin-scheduled Clan Wars with two active clans, scheduled start, result finalization/cancellation, audited outcomes and idempotent winner/draw Clan EXP ledger awards. `/clan-wars` lists scheduled and completed matches; leaderboard now reports wins-losses-draws. Migration `0037_clan_missions` adds versioned Admin-configured Clan missions with daily/weekly/one-time cadence, registered trusted event triggers, cycle-pinned progress, exactly-once Clan EXP and final-contributor EXP/Coin rewards. Migration `0038_clan_war_proposals` adds course-event-permission-gated staff proposals and an Admin approval queue; reward is set at approval. Owner transfer is audited and available to the Clan owner. The Clan screen connects these workflows with progress, configuration, proposal submission/review and ownership controls. Migration `0039_shop_exp_vouchers` adds allowlisted effect configuration and one-time server-ledger EXP voucher redemption. The Admin shop form can publish a bound voucher; inventory displays its configured amount and redeems it once. Migration `0040_shop_scheduled_discounts` adds one Admin-managed, timezone-aware discount window per catalog item; Admin can schedule, replace or clear it. Store views show original and active discounted prices, and purchase settlement calculates the current discount under the locked item transaction.

- Migration `0041_user_exp_multipliers` persists each account’s x2 EXP window. Admin can publish a bound x2 item for 1–168 hours; activation extends remaining time, remains capped at x2, and the shop, inventory, and wallet show configuration and active expiry. Trusted EXP ledger rewards from missions, achievements, Clan missions, and vouchers use one multiplier-aware writer; Coin is unchanged. Ledger details record base EXP and bonus EXP.
- Migration `0042_mission_streak_boosts` adds mission-bound, expiring streak cards. Activation grants progress to three without issuing a reward; the next qualifying trusted event consumes the boost and issues the normal reward. Expiry removes only progress granted by the card. Admin mission/duration controls and Student inventory activation/status are connected.
- Migration `0043_user_equipped_shop_titles` lets purchased bound titles use the same single title slot as achievement titles; users can clear or re-equip their owned title. Admin catalog title text and Student title status are connected.
- Migration `0044_shop_exp_prices` adds atomic dual Coin/EXP item pricing. The catalog shows both balances and the purchase transaction refuses insufficient balance before charging either currency.
- Migration `0045_marketplace_policies` adds audited immutable policy versions for listing/offer fees, price and per-user volume limits, and expiry caps. Listings and offers snapshot policy version and fee. Fixed-price purchases and accepted Coin offers append seller fee-burn ledger entries; dispute reversal debits only net seller proceeds, retaining the already burned fee. `/marketplace` includes an Admin policy editor and discloses computed fees/net proceeds before buy/offer acceptance.
- Migration `0046_shop_refunds` adds immutable enabled/disabled refund rules and a 1–168 hour window, captured by each new purchase. A buyer can request a refund for an in-window purchase when all purchased units are unused and unequipped; the request reserves the items. Admin approval appends idempotent Coin and EXP credits and restores stock; rejection returns the items to inventory. Both actions are audited. `/shop` and `/inventory` now show purchase history/request controls; the Admin view publishes policy versions and reviews the pending queue.
- Migration `0047_clan_competition_rewards` adds typed Clan War/code/writing events, participant reward snapshots and one award receipt per selected active member. Admin may configure per-participant EXP, Coin and supported shop items; staff proposals select the event type and Admin sets rewards on approval. The Clan UI loads eligible members, allows Admin selection, and records participant awards atomically with finalization. Retry with the same result and participant set is idempotent.
- Competition item grants use a deterministic UUID purchase reference to fit the inventory column and prevent duplicate grants. A guarded stress verifier upgrades only `codemark_lms_test` with a private backup and races two identical result submissions; both requests return 200 while exactly one Clan EXP, participant EXP, Coin, and item reward is written.
