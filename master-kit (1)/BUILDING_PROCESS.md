## Operating rules

- Keep the active task, ordered steps, validation evidence, blockers, and next task current in this file.
- Use `[x]` only for implemented and validated work. Keep unimplemented contract requirements explicitly pending.
- Preserve completed history and never reuse an ID. BUILD-000 through BUILD-002 are complete; BUILD-003 and BUILD-004 through BUILD-011 are superseded by this replan and are not represented as completed.
- New task IDs continue at BUILD-012. Run one active task at a time; update this file before moving to the next task.
- When a task is validated, record its `Done BUILD-<ID>` and keep the next task Pending until work actually starts; then mark it Active before editing.
- Each task must describe user-visible or operational output, its dependencies, and concrete acceptance checks. Record regressions and retries.
- Do not mark a feature Done merely because a static mockup or placeholder screen exists. Label demo data and unavailable workflows honestly.
- No production secrets or real student data in local demos. Keep assets self-hosted and runtime egress denied by default.
